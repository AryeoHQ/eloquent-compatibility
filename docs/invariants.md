# Invariants

Each rule below holds today, and a change must keep it. Each names the code that must agree and the tests that pin it. Where no test pins a rule, the entry says so: a change there needs a reviewer's eye, or a new test.

## INV-1: Locks follow one order

**Rule.** The event bridge and the triggers lock the primary row before the retained row. For a dependent model's write, the bridge locks the primary row of each primary foreign key the write names. The bridge and the update trigger lock the dependent rows last. A `FOR UPDATE` read through the view locks the primary row before the retained row. A refuse function on a dependent's table or the retained table locks the primary row before it takes the refused-state lock. `EventBridge::mirror()` refuses a map that would make one model the primary current model of one mirrored map and a dependent current model of another.

**Why.** The bridge locks before the statement, and the trigger locks the same rows again. Two writers that take locks in one order cannot deadlock on these rows. A model in both roles has no such order. One map locks its row before that map's retained row, and the other map's triggers lock it after theirs. A bridged write of that model then deadlocked a concurrent write through the other view with 40P01.

The view's order relies on PostgreSQL's observed row locking, which its documentation does not state. ExecLockRows locks the rows in row-mark order, and the planner builds the row marks in range-table order. So the order of the view's `FROM` list sets the order of the locks. The deadlock tests pin it on PostgreSQL 14, 16 and 18.

**Exceptions.** Two lock paths do not follow the order:

- **A writer that locks a dependent row before the primary row.** It can deadlock a concurrent update through the view with 40P01. The view writer holds the primary row `FOR UPDATE` and waits on the dependent row, which `Compiler::conflict()` locks on every update. A raw update locks the dependent row first, and its refuse function's `FOR KEY SHARE` on the primary row then waits on the view writer. A write through the event bridge locks the primary row before its statement, so it waits instead. It still deadlocks when the application locked the dependent row itself before the write.
- **A newcomer record in the bridge's second pass.** `AffectedRecords::before()` calls `AffectedRecords::of()` again under its first locks, for every operation. A record found only on that second call is a newcomer, such as a dependent row another transaction committed before the first lock, or another map's previous record for it. The bridge locks the newcomers after every record of the first pass, sorted by `RecordRole::lockOrder()` among themselves. The role order does not hold across the two passes.

**Code that must agree.** `RecordRole::lockOrder()` puts primary records first, previous records second and dependent records last. The private `AffectedRecords::lock()` sorts by it, then by lock table and key. `AffectedRecords::before()` adds a dependent write's primary records from the private `AffectedRecords::lockedOnly()`, so it locks them and snapshots none. `KeyTranslator::previousRecord()` makes a previous record lock its retained table. `Compiler::updateFunction()` and `Compiler::deleteFunction()` call `Compiler::lockPrimary()` before `Compiler::loadPrevious()`. `Compiler::conflict()` then locks each dependent row the record reads. `Compiler::refuseFunction()` takes `FOR KEY SHARE` on the primary row before `pg_advisory_xact_lock()`. `Compiler::view()` names the primary table first in the view's `FROM` list, and joins the retained table to it. `EventBridge::mirror()` compares each current model's role with its role in every map already mirrored, through `MirrorIndex::forModel()`, before it registers the map.

**Pinned by.** `EventBridgeTest::it_refuses_to_mirror_a_map_whose_current_model_another_mirrored_map_names_in_the_other_current_role()` pins the refusal, in both orders of registration. `InstallerTest::it_does_not_deadlock_a_write_through_the_view_against_a_writer_holding_the_refused_state_lock()` pins the refused-state lock's place in the order, with a second writer in a child process. `AffectedRecordsTest::it_locks_the_primary_row_then_the_retained_row_then_the_dependent_rows_before_a_previous_model_write()`, `AffectedRecordsTest::it_locks_the_own_row_of_a_current_model_in_the_same_order_and_snapshots_only_the_records_it_mirrors()`, `AffectedRecordsTest::it_locks_the_records_of_one_role_by_table_and_then_by_key()` and `AffectedRecordsTest::it_locks_the_retained_rows_of_every_map_over_a_current_record_in_table_order()` pin the bridge's order. `AffectedRecordsTest::it_locks_every_primary_row_a_dependent_write_names_before_its_retained_rows_and_snapshots_none_of_them()` pins a dependent's insert and its move between primary rows. `RecordRoleTest::it_locks_the_primary_record_first_then_the_previous_record_then_the_dependent_records()` pins `RecordRole::lockOrder()`. `AffectedRecordsTest::it_locks_a_dependent_row_that_appears_under_the_first_locks_after_them_and_snapshots_it()` pins the newcomer exception for a removing delete, and `EventBridgeOutsideTransactionTest::it_raises_the_update_events_of_a_readable_dependent_row_committed_before_the_primary_record_is_locked()` pins it for an update. `EventBridgeOutsideTransactionTest::it_does_not_deadlock_a_lock_through_the_view_against_a_bridged_update_of_the_same_record()` and `InstallerTest::it_does_not_deadlock_a_lock_through_the_view_against_an_update_through_the_view_that_holds_the_primary_row()` pin the view's order, each with the lock through the view in a child process. No test pins the dependent-row deadlock exception, the bridged write that waits instead, or the order of the primary and retained locks inside the triggers.

The second pass has limits. It finds every dependent row another transaction inserts, because an insert that has not committed by the first lock waits on the locked primary row. Its foreign key check takes `FOR KEY SHARE` on that row. This holds only when each dependent's primary foreign key has a foreign key constraint to the primary table, or the dependent's table has a refuse function. The package does not require either. Without one, a row another transaction inserts after the second pass can escape it: a removing delete then removes that row without its delete events, and an update replays the row's create events in place of its update events. An update can make an existing dependent row readable without changing its primary foreign key, so it takes no lock on the primary row. Only a refuse function on that dependent's table blocks such an update, because the refuse function takes `FOR KEY SHARE` on the primary row first. The workbench place has one, `second_root_place`. Without one, that update can commit after the second pass. The bridge then holds no row from before for that dependent row, and it replays the row's create events in place of its update events.

## INV-2: One expression locates a dependent row

**Rule.** The view, the update trigger and the event bridge pick a dependent row with the same subquery, from `ResolvedMap::locate()`.

**Why.** The bridge must mirror the row the view reads and the trigger writes. Two copies of the condition could pick two rows. A delete that removes the row is the one exception: the trigger removes every dependent row, and INV-25 mirrors them all.

**Code that must agree.** `ResolvedMap::locate()`, called by `Compiler::read()`, `Compiler::updateDependent()` and `KeyTranslator::currentKeys()`.

**Pinned by.** `DependentCurrentModelTest::a_previous_model_write_mirrors_only_the_designated_dependent_row()` and `DependentCurrentModelTest::the_previous_model_reads_no_dependent_row_once_its_designated_row_is_no_longer_readable_and_reads_no_other()`. `KeyTranslatorTest::it_translates_a_previous_key_into_the_key_of_each_current_record_the_view_reads()` pins the row the bridge picks over a child row and a soft-deleted row.

## INV-3: The view's own writes skip this map's current-side triggers

**Rule.** The insert, update and delete triggers hold the applying flag at the map's name while they run. Each one restores the flag's earlier value when it returns. The primary insert, primary delete and designate triggers return early while it holds that name.

**Why.** An insert through the view writes the primary row itself. Without the flag, the primary insert trigger would add a second retained row. The flag holds the map's name, so another map over the same primary table still reacts. An application trigger can write through a second compatibility view inside the first view's write. The triggers once cleared the flag after their writes, so that nested write cleared the outer map's name. The outer primary insert trigger then added a second retained row.

**Code that must agree.** `Setting::Applying` and `Setting::for()`. `Compiler::function()` gives `Compiler::insertFunction()`, `Compiler::updateFunction()` and `Compiler::deleteFunction()` a `SET` clause for the flag. PostgreSQL then sets it on entry and restores it on exit, an exit by an error included. `Compiler::skipWhileApplying()` in `Compiler::primaryInsertFunction()`, `Compiler::primaryDeleteFunction()` and `Compiler::designateFunction()`.

**Pinned by.** `InstallerTest::it_inserts_one_record_into_every_table_and_returns_the_previous_model_key()` asserts one retained row. `InstallerTest::it_keeps_two_previous_models_over_one_current_record_in_step()` asserts that the other map reacts. `InstallerTest::it_keeps_one_retained_row_per_primary_row_when_a_trigger_inside_a_write_through_the_view_writes_through_another_compatibility_view()` pins the nested write, with an `AFTER INSERT` trigger on `gadgets` that inserts through `accounts`.

## INV-4: Every database refusal is CM001

**Rule.** Every refusal the compiled SQL raises uses SQLSTATE CM001, with a message, a detail and a hint.

**Why.** PHP recognises a refusal by that one code. It splits the three parts into what was refused, why, and what to do instead.

**Code that must agree.** `SqlState::Refused`, `SqlFragments::refuse()` and `SqlFragments::raise()`. Every refusal in `Compiler` calls `SqlFragments::refuse()`: in `Compiler::updateFunction()`, `Compiler::notNullChecks()`, `Compiler::updateDependent()`, `Compiler::missing()` and `Compiler::refuseFunction()`. `CompatibilityWriteRefused::isRefusal()` and `CompatibilityWriteRefused::fromQueryException()` read it back.

**Pinned by.** `InstallerTest::it_refuses_a_change_to_a_read_only_attribute_with_what_why_and_what_to_do()` reads the three parts. `EventBridgeOutsideTransactionTest::it_rolls_back_its_transaction_when_a_queued_bridged_write_fails_so_the_worker_records_the_failed_job()` asserts the literal CM001. `InstallerTest::it_fails_loudly_on_writes_a_view_with_triggers_cannot_take()` asserts that other failures are not refusals. `SqlFragmentsTest::it_refuses_with_a_message_expression_and_a_quoted_detail_and_hint_that_php_reads_back()`, `SqlFragmentsTest::it_raises_the_given_sqlstate_with_its_message_detail_and_hint()` and `SqlStateTest::it_names_the_refusal_code_and_the_serialization_failure_code()` pin the SQL side. `CompatibilityWriteRefusedTest::it_counts_itself_and_a_query_refused_by_the_database_as_a_refusal_and_nothing_else()` and `CompatibilityWriteRefusedTest::it_splits_a_refusal_the_database_raised_into_its_message_detail_and_hint()` pin the PHP side.

## INV-5: A concurrent change raises 40001

**Rule.** After its locks, the update trigger locks each dependent row the record reads, then reads every attribute again. When that read differs from `OLD`, it raises SQLSTATE 40001, not CM001. A dependent row it no longer finds is not a conflict: its attributes compare as `OLD`. The trigger then writes only the dependent row it locked. When it locked none, but the view's subquery finds a row now, it raises 40001 too.

**Why.** An INSTEAD OF trigger receives `OLD` from the statement's snapshot. A change committed after that snapshot would otherwise be overwritten. A serialization failure tells the caller to retry.

**Code that must agree.** `Compiler::conflict()`, called in `Compiler::updateFunction()` after `Compiler::loadPrevious()`. It locks each dependent row through `ResolvedMap::locate()` into its `key_<alias>`, and joins that row by its key. It reads each other attribute with `Compiler::read()`, as the view does. It compares each attribute as [INV-36](#inv-36-an-attribute-without-a-btree-equality-compares-as-text) requires, and raises `SqlState::SerializationFailure`. `Compiler::updateDependent()` writes the row in `key_<alias>`, and selects no row of its own. Both raise through the private `Compiler::concurrentChange()`. `CompatibilityWriteRefused::isRefusal()` must not accept it.

**Pinned by.** `CompilerTest::it_raises_a_serialization_failure_when_a_primary_or_retained_attribute_changed_after_the_statement_read_the_view()`, with a primary and a retained change. `CompilerTest::it_raises_a_serialization_failure_when_a_dependent_attribute_changed_after_the_statement_read_the_view()` pins a changed place and a changed site, whether or not the stale write touches the dependent attribute. `CompilerTest::it_lets_a_write_through_proceed_when_its_dependent_row_is_gone_after_the_statement_read_the_view()` pins that a missing dependent row is not a conflict. `CompilerTest::it_raises_a_serialization_failure_when_the_dependent_row_it_waited_on_stops_being_readable_and_another_becomes_readable()` pins the row found only after the lock, with a second connection.

## INV-6: A change to a shared current table mirrors every previous model over it

**Rule.** When a current record changes, every map with a previous model over that record's table raises its previous model's events. That holds when another map names a different model class over the same table.

**Why.** Two previous models can read one current row. A write through either side must reach the listeners of both. The bridge finds a model's maps by its exact class, so a write through one class over the table once missed the maps of the other class.

**Code that must agree.** `AffectedRecords::acrossMaps()`, `MirrorIndex::forRelation()`, `MirrorIndex::add()` and `KeyTranslator::previousKeys()`. `AffectedRecords::of()` hands `AffectedRecords::acrossMaps()` the current model's own record in each of its maps too, and leaves that record out of the result.

**Pinned by.** `EventBridgeTest::it_raises_the_events_of_every_previous_model_over_one_current_record()` and `AffectedRecordsTest::it_finds_the_previous_records_of_every_other_map_over_a_current_record()`. `EventBridgeTest::it_raises_the_events_of_every_previous_model_over_a_current_table_that_another_model_class_maps()` pins a second class over `people`, with a veto on its map. `MirrorIndexTest::it_lists_the_maps_and_aliases_of_each_current_table_and_of_no_view_or_retained_table()` pins `MirrorIndex::forRelation()`, and `KeyTranslatorTest::it_lists_every_previous_key_over_a_primary_key_in_key_order()` pins `KeyTranslator::previousKeys()`.

## INV-7: The update trigger writes only what changed

**Rule.** The update trigger writes a table only when one of its attributes changed, and a column's value only when its own attribute changed. Its `UPDATE` assigns every mapped column of that table, retained table included, and an unchanged column gets its own stored value. So PostgreSQL fires an `UPDATE OF` trigger on that table for a write that did not change its column. `compatibility:check` warns of each such trigger without a `WHEN` clause, and its exit status stays the same.

**Why.** An unchanged table keeps its rows as they are, and fires none of its triggers. A column whose attribute did not change keeps the value stored now. PostgreSQL fires an `UPDATE OF` trigger for each column in the `SET` list, changed or not. The SQL stays as it is, and the check names each trigger that needs a guard. The event bridge compares rows, not `SET` lists, so its events are unaffected.

**Code that must agree.** `SqlFragments::changed()`, `Compiler::updateTable()`, `Compiler::updateDependent()` and `Compiler::update()`. `DriftQueries::unguardedColumnTriggers()` reads the same `ResolvedMap::assignmentsTo()` targets as `Compiler::update()`, for each current table and for the retained table, and `CheckDrift::handle()` prints its result without a change to the exit status.

**Pinned by.** `InstallerTest::it_writes_only_the_tables_whose_attributes_changed()`. `CheckDriftTest::it_warns_of_each_unguarded_update_of_trigger_on_a_mapped_column_and_still_passes()` pins the warning, with a trigger on a written retained column, a guarded trigger, an unmapped column on a current table and on the retained table, a map's own trigger and a trigger without a column list left out. `EventBridgeTest::it_raises_nothing_for_a_write_that_changes_no_attribute_of_the_other_side()` pins the result the bridge sees. `SqlFragmentsTest::it_tells_whether_any_listed_column_changed_counting_null_as_a_value()` pins `SqlFragments::changed()`.

## INV-8: Each stored column has one owner

**Rule.** At most one attribute writes a given column, and no attribute writes the primary foreign key or a designation column. A read-only attribute stored in a column that a writable attribute writes yields to that owner on insert. Two or more read-only attributes stored in one column need a writable owner, or registration refuses the map. A fill from `PrimaryCurrentModel::fillWhenCreatedFromPrevious()` or `DependentCurrentModel::fillWhenCreatedFromPrevious()` never sets a column an attribute writes. Registration refuses an attribute that stores a dependent's primary foreign key, read-only or not. It also refuses a fill that sets a dependent's primary foreign key, the retained table's primary foreign key or a designation column.

**Why.** The update trigger writes each column from one attribute's change. The map maintains the link and the designation itself. An insert stores a read-only attribute too, as [INV-49](#inv-49-an-insert-through-the-view-stores-a-read-only-attribute) says. A read-only `title_copy` stored in the column of a writable `title` therefore overwrote `title` with NULL. With no writable owner, nothing says which read-only value an insert stores. An insert writes a dependent's link first and its attributes and fills after, so an attribute stored in `gadget_places.gadget_id` replaced the link. The new place then belonged to another gadget. A retained fill of `gadget_id` likewise left a native gadget's retained row unlinked.

**Code that must agree.** `ResolvedMap::validateAttributes()`, the private `ResolvedMap::validateLinks()`, `Compiler::validateColumns()` and `Compiler::insertValues()`. `ResolvedMap::validateLinks()` reads each attribute's `Attribute::$writesTo` and its `Attribute::$storedAs`, so a read-only attribute counts too. The private `Compiler::insertAssignmentsTo()` skips a read-only mapped attribute whose column `ResolvedMap::writes()` reports.

**Pinned by.** `ResolvedMapTest::it_refuses_two_attributes_that_own_one_stored_column()`, `ResolvedMapTest::it_refuses_two_read_only_attributes_stored_in_one_column_that_no_writable_attribute_owns()`, `ResolvedMapTest::it_refuses_a_read_only_mapped_attribute_stored_in_the_column_of_a_read_only_retained_attribute()`, `ResolvedMapTest::it_accepts_read_only_attributes_stored_in_a_column_that_a_writable_attribute_owns()`, `CompilerTest::it_stores_the_writable_attribute_when_a_read_only_attribute_is_stored_in_the_same_column()`, `ResolvedMapTest::it_refuses_an_attribute_the_tables_cannot_store()` and `DependentCurrentModelTest::it_refuses_an_attribute_that_writes_the_designation()`. `CompilerTest::it_refuses_at_compile_time_a_map_the_tables_cannot_store()` pins the fill collision, in its `primary_fill_collision` and `dependent_fill_collision` cases. `ResolvedMapTest::it_refuses_at_registration_an_attribute_or_a_fill_that_sets_a_column_linking_the_record()` pins the links through `CompatibilityMaps::register()`. It covers a writable, a read-only and a `writesTo()` dependent attribute, a dependent fill, a retained fill and a designation fill.

## INV-9: Each map owns a prefix no other map's prefix begins

**Rule.** Every trigger and function of a map starts with `compatibility__<name>__` and fits in 63 characters. A map name has at most 24 lowercase letters, digits and single underscores, and does not end in an underscore. The Installer drops only the prefixed triggers on the current schema's tables, the prefixed functions of that schema and the view in that schema.

**Why.** The Installer finds a map's triggers and functions by prefix and schema alone. A name with a double or trailing underscore could make one map's prefix begin another's. Uninstalling one map would then drop the other's objects. Without the schema, an install in one schema would drop the same map's triggers in another, or a trigger on another schema's table.

**Code that must agree.** `ResolvedMap::of()` checks the name. `ResolvedMap::objectPrefix()`, `ResolvedMap::functionName()`, `ResolvedMap::refuseFunctionName()` and `ResolvedMap::designateFunctionName()` build every name, through the private `ResolvedMap::object()`. `Installer::dropObjects()` matches the prefix through `SqlFragments::like()`. It drops a trigger only when its table and its function are both in `current_schema()`, and a function only when it is in that schema. It names the schema through `to_regnamespace(quote_ident(current_schema()))`, so a schema whose name needs quoting resolves. The private `Installer::relation()` looks the view up in that schema alone. `Installer::install()` refuses when it finds one, `Installer::recompile()` replaces it only when it finds one, and `Installer::uninstall()` drops it only when it finds one. `Compiler` creates every function in that same schema.

**Pinned by.** `ResolvedMapTest::it_refuses_a_name_that_cannot_prefix_database_objects()`, `InstallerTest::it_recompiles_a_compatibility_map_without_duplicating_its_triggers()` and `InstallerTest::it_uninstalls_the_compatibility_view_and_leaves_the_current_models_untouched()`. `InstallerTest::it_leaves_the_same_compatibility_map_in_another_schema_installed()` and `InstallerTest::it_keeps_a_prefixed_trigger_on_another_schemas_table_that_calls_a_function_of_this_schema()` pin the schema. `InstallerTest::it_installs_recompiles_and_uninstalls_in_a_schema_whose_name_needs_quoting()` pins a quoted schema name. `InstallerTest::it_installs_recompiles_and_uninstalls_ahead_of_a_later_schema_that_has_the_compatibility_map()` and `InstallerTest::it_uninstalls_nothing_of_a_later_schema_when_the_current_schema_has_no_compatibility_view()` pin the view's schema. `SqlFragmentsTest::it_matches_only_values_that_begin_with_the_prefix_taken_literally()` pins `SqlFragments::like()`. `CompilerTest::it_refuses_at_compile_time_a_map_the_tables_cannot_store()` pins the 63-character limit in its `long_refuse_function` and `long_designate_function` cases. `CompilerTest::it_installs_an_object_name_of_exactly_63_characters_without_truncating_it()` and `CompilerTest::it_compiles_every_trigger_function_of_a_map_whose_name_has_the_most_characters_allowed()` pin the limit's edge.

## INV-10: Reads and writes carry their types

**Rule.** The view casts each mapped attribute to its declared type. The triggers cast each written value to its column's type in the catalog. The compiler names each catalog type and default as the trigger functions' `search_path` resolves it. So a type or a default from another schema carries that schema, and the compiling connection keeps its own search path.

**Why.** A mapped attribute's type can differ from the column that stores it. The workbench `price` is text in the view and integer cents in `gadgets`. PostgreSQL leaves out the schema of a type or a function that the current search path finds. An enum from a later schema on the installer's search path therefore compiled unqualified. The functions search only the installation schema and `pg_temp`, so every write through the view then failed with 42704.

**Code that must agree.** `ResolvedMap::validateAttributes()` requires `Attribute::asType()`. `Compiler::read()` casts reads, and `Compiler::value()` casts writes through `ColumnCatalog::type()`. The private `Compiler::searchPath()` names the search path for both `Compiler::function()` and the `Compiler`'s `ColumnCatalog`. `ColumnCatalog::of()` reads under that search path inside a transaction or savepoint it rolls back. `EventReplayer` builds its `ColumnCatalog` without one, so it reads in one statement under the connection's search path.

**Pinned by.** `InstallerTest::it_exposes_every_attribute_with_its_declared_previous_model_type()`, `InstallerTest::it_stores_a_renamed_and_retyped_attribute_once_in_its_owner()` and `ResolvedMapTest::it_refuses_a_mapped_attribute_without_a_type_when_the_map_is_registered()`. `ColumnCatalogTest::it_gives_the_type_of_a_column_or_none_for_a_column_the_table_does_not_have()` pins `ColumnCatalog::type()`. `CompilerTest::it_writes_a_column_whose_type_and_default_come_from_a_later_schema_on_the_search_path()` pins a `NOT NULL` enum column with a default, from a schema after the installation schema. It also pins that the install leaves the search path as it was. `ColumnCatalogTest::it_names_a_type_and_a_default_as_its_search_path_finds_them_and_leaves_the_connections_own()` pins both readers inside a caller's transaction, where a released savepoint would keep the narrower search path.

## INV-11: A write through the view needs both rows

**Rule.** An update or delete through the view refuses with CM001 when the retained row is missing. An update that writes the primary row also refuses when it touches other than one row.

**Why.** A write with nowhere to store its change would otherwise succeed silently. The hint points at `compatibility:check`.

**Code that must agree.** `Compiler::loadPrevious()`, `Compiler::updateTable()` for the primary alias, and `Compiler::missing()`.

**Pinned by.** `CompilerTest::it_refuses_a_write_through_the_view_whose_retained_row_is_gone()`, with an update and a delete, and with the hint that names `compatibility:check`. `CompilerTest::it_refuses_a_write_through_the_view_that_updates_no_primary_row()`.

## INV-12: A designation pins the dependent row

**Rule.** When a dependent declares a designation, the previous model uses only the row it names. It reads, writes and mirrors that row only while the row is readable. A write to a dependent attribute refuses while the named row exists but is not readable.

**Why.** Without it, the previous model would switch to another row when the first stops matching its readable condition.

**Code that must agree.** `ResolvedMap::locate()` adds the designation to the condition. `Compiler::designateFunction()` fills an empty designation when an insert or an update makes a dependent row readable. `Compiler::triggers()` attaches it `AFTER INSERT OR UPDATE`. `Compiler::designate()` sets the designation for rows the view creates. `Compiler::updateDependent()` refuses, and `Compiler::validateColumns()` requires the column. `DriftQueries::brokenDesignations()` reports a broken designation, and an empty one whose record has a readable row.

**Pinned by.** Every test in `DependentCurrentModelTest`, for example `DependentCurrentModelTest::a_previous_model_write_to_a_dependent_attribute_is_refused_while_the_designated_row_is_not_readable()`. `DependentCurrentModelTest::a_dependent_row_that_becomes_readable_through_an_update_fills_an_empty_designation()` pins the update. `DriftQueriesTest::it_finds_an_empty_designation_whose_record_has_a_readable_row()` pins the empty designation's finding.

A record that already exists at install time has no designation. [Adopting a map](adopting-a-map.md) describes the backfill.

## INV-13: Hidden records are hidden from the drift check too

**Rule.** A record a hidden state covers is absent from the view, and the drift check does not report it.

**Why.** A hidden record has no current rows on purpose. Reporting it would make the check fail on every run.

**Code that must agree.** `Compiler::view()`, `DriftQueries::previousWithoutCurrent()` and `DriftQueries::brokenDesignations()` build the same `COALESCE((condition), false)` test.

**Pinned by.** `InstallerTest::it_hides_the_records_a_hidden_state_names()`, `CheckDriftTest::it_passes_when_every_record_has_its_previous_and_current_models()` and `DriftQueriesTest::it_leaves_out_a_retained_row_a_hidden_unrepresentable_state_covers_and_no_other()`.

## INV-14: A refused state checked on a table holds for every writer

**Rule.** A refused state that names `UnrepresentableState::checkedOn()` compiles to a trigger on that table, which runs for every insert and update, the view's included.

**Why.** The state is unrepresentable whoever writes it, and the applying flag does not exempt the view.

**Code that must agree.** `Compiler::refuseFunction()`, which never calls `Compiler::skipWhileApplying()`. `Compiler::triggers()` attaches it `BEFORE INSERT OR UPDATE`. `DriftQueries::refusedStates()` reports rows already in the state.

**Pinned by.** `InstallerTest::it_applies_a_refused_state_to_every_write_that_reaches_it()` and `CheckDriftTest::it_names_the_record_and_the_attribute_of_each_divergence_made_by_hand()`. `CompilerTest::it_attaches_each_trigger_function_to_its_table_and_events()` pins the `BEFORE INSERT OR UPDATE` trigger, and `DriftQueriesTest::it_finds_each_record_in_a_refused_state()` pins the drift query.

The trigger checks each writer against committed rows and its own. On the primary table, two concurrent writers can both reach a cross-row state, as INV-23 records.

## INV-15: A mirrored listener may refuse a write, never change it

**Rule.** A mirrored `-ing` listener that returns false, or changes an attribute, refuses the whole write with `CompatibilityWriteRefused`.

**Why.** The write has already reached the database when mirrored events fire, so a listener's change has nowhere to go.

**Code that must agree.** `EventReplayer::ing()`, `EventReplayer::changed()` and `EventReplayer::equivalent()`. `EventReplayer::equivalent()` compares by the attribute's cast, or else by its column type, which `EventReplayer::changed()` reads through `ColumnCatalog` only when a value changed. A numeric cast or column compares two numbers through `EventReplayer::number()`, by their exact decimal value, never through a float. So a change below float precision still counts. A JSON cast or a `json` or `jsonb` column compares the decoded JSON, through the private `EventReplayer::json()`. An object and an array differ, empty or nested, and the order of an object's keys does not count. `EventReplayer::json()` reads each JSON number from its text through `EventReplayer::number()`, never through a PHP integer or float. So two integers past PHP's integer range differ, and so do two fractions a float cannot tell apart. A number that `EventReplayer::number()` cannot read refuses the write. An encrypted cast or a class cast compares as Laravel's `Model::originalIsEquivalent()` does, on a copy of the model whose original holds the value from before the listener. Such a cast can store a new string for a value a listener only read: `Illuminate\Database\Eloquent\Casts\AsEncryptedCollection` encrypts again with a new IV. Every other attribute, a text column included, compares exactly, so `'1'` and `'001'` differ. `CompatibilityWriteRefused::byMirroredListener()` and `CompatibilityWriteRefused::byMirroredChange()` build the refusals.

**Pinned by.** `EventBridgeTest::it_rolls_back_the_whole_write_when_a_mirrored_listener_refuses()` and `EventBridgeTest::it_refuses_a_mirrored_listener_that_changes_the_mirrored_record()`. `EventBridgeTest::it_refuses_a_mirrored_listener_change_to_a_number_that_a_float_cannot_tell_apart()` and `EventBridgeTest::it_accepts_a_mirrored_listener_that_rewrites_a_number_as_the_same_value()` pin the number comparison. `EventReplayerTest::it_refuses_the_write_when_a_mirrored_listener_of_an_ing_event_returns_false()`, `EventReplayerTest::it_lets_a_mirrored_listener_of_an_ed_event_return_false()`, `EventReplayerTest::it_refuses_the_write_when_a_mirrored_listener_changes_the_record()`, `EventReplayerTest::it_refuses_a_listener_change_to_a_number_that_a_float_cannot_tell_apart()` and `EventReplayerTest::it_accepts_a_listener_rewrite_to_the_same_number_in_a_numeric_column_or_the_same_json_in_a_json_column()` pin the same rule on `EventReplayer::replay()` alone. `EventReplayerTest::it_refuses_a_listener_change_to_a_text_column_that_reads_as_the_same_number_or_json()` and `EventReplayerTest::it_accepts_a_listener_rewrite_to_the_same_value_of_a_text_column_cast_to_a_number_or_to_json()` pin the column type and the cast. `EventReplayerTest::it_refuses_a_listener_change_of_a_json_column_between_an_object_and_an_array()` and `EventReplayerTest::it_accepts_a_listener_rewrite_of_a_json_column_that_only_reorders_the_keys_of_its_objects()` pin the JSON kinds and key order. `EventBridgeTest::it_refuses_a_mirrored_listener_change_to_a_json_number_that_php_cannot_tell_apart()` and `EventBridgeTest::it_accepts_a_mirrored_listener_that_rewrites_json_as_the_same_numbers_with_its_keys_reordered()` pin the JSON numbers. `EventBridgeTest::it_accepts_a_mirrored_listener_that_only_reads_an_encrypted_collection()` pins a class cast.

## INV-16: A mirrored listener's write begins its own pending write

**Rule.** A native write inside a mirrored listener begins its own pending write, on top of the connection's stack. That holds for a write on the instance the bridge replays too.

**Why.** The replay's own events never reach the bridge. `EventReplayer::replay()` dispatches them through the model dispatcher, never through `HasCompatibility::fireModelEvent()`. So the bridge sees a beginning event on a replayed instance only when a listener writes that instance. That write sends its own statement. The bridge once ignored it, and the write then ran inside the bridge's transaction with no lock, no snapshot and no mirrored events.

**Code that must agree.** `EventReplayer::replay()`, `EventBridge::begin()` and `EventBridge::top()`. The private `EventBridge::sees()` tells no replayed instance apart.

**Pinned by.** `EventBridgeTest::it_mirrors_a_write_a_mirrored_listener_makes_as_a_change_of_its_own()` and `EventBridgeTest::it_runs_an_excluded_listener_for_a_native_write_inside_a_mirrored_event()`. `EventBridgeTest::it_mirrors_a_write_a_mirrored_listener_makes_on_the_instance_it_was_given()` pins a write on the replayed instance.

## INV-17: A delete completes on an UPDATE

**Rule.** A pending delete opens and completes on the statement its model's own save query sends. For a soft delete, that statement is an `UPDATE` of the deleted-at column. [INV-33](#inv-33-a-pending-write-completes-only-on-its-own-statement) states the full rule.

**Why.** Eloquent sends a soft delete as an `UPDATE` of the deleted-at column.

**Code that must agree.** `ModelEvent::operation()`, `HasCompatibility::setKeysForSaveQuery()` and `EventBridge::markOwnStatement()`. `AffectedRecords::of()` reads a soft delete from `Operation::Delete` and the model's `isForceDeleting()`, never from the statement.

## INV-18: An excluded listener skips mirrored dispatches only

**Rule.** An excluded listener is skipped only while the bridge dispatches for the instance it replays. It runs for every native event, including one raised inside a mirrored listener. That holds for a listener registered under the event's name and for one registered by a wildcard, such as `eloquent.updated: *`, on Laravel's own dispatcher.

**Why.** An event mirror excludes a listener from writes through the other side, not from the model's own writes. Laravel keeps wildcard listeners apart from the listeners of each name, so masking the name alone once left a wildcard listener running for mirrored events.

**Code that must agree.** `EventReplayer::dispatch()`, `EventReplayer::mask()`, `EventReplayer::guard()` and `EventReplayer::unmask()`. The `Exclusion` is held per subject. `ExcludedListener::matches()` matches the listener. `EventReplayer::dispatch()` masks the listeners on the real dispatcher behind an `EventFake`, and dispatches through the model's dispatcher. So a faked event is recorded, and none of its listeners runs. The private `EventReplayer::maskWildcards()` wraps each listener of every wildcard that matches the event, in place, through the dispatcher's protected `$wildcards`. Its wrapper keeps the wildcard arguments, the event name and the payload. The private `EventReplayer::unmaskWildcards()` restores them, so the wildcards keep their order. Both need an `Illuminate\Events\Dispatcher`, so a decorating dispatcher keeps its wildcard listeners unmasked.

**Pinned by.** `EventBridgeTest::it_skips_an_excluded_listener_registered_by_wildcard_for_mirrored_events_only()` pins a wildcard listener, for a mirrored event and for a native event inside a mirrored listener. `EventBridgeTest::it_skips_an_excluded_listener_for_mirrored_events_only()`, `EventBridgeTest::it_skips_an_excluded_listener_and_records_each_mirrored_event_once_through_a_decorating_dispatcher()`, `EventBridgeTest::it_skips_an_excluded_listener_for_a_mirrored_create_through_a_decorating_dispatcher_and_runs_it_for_a_native_create()` and `EventBridgeTest::it_runs_an_excluded_listener_for_a_native_write_inside_a_mirrored_event()`. `EventReplayerTest::it_skips_an_excluded_listener_for_its_replayed_event_only()` and `EventReplayerTest::it_skips_an_excluded_listener_under_a_fake_that_leaves_model_events_alone()` pin the masking, and `ExcludedListenerTest` pins `ExcludedListener::matches()`. `EventBridgeTest::it_records_a_faked_mirrored_event_and_runs_none_of_its_listeners_when_the_map_excludes_a_listener()` and `EventReplayerTest::it_records_a_faked_event_without_running_its_listeners_when_the_map_excludes_a_listener()` pin a faked event.

## INV-19: A failed write at level 0 releases its transaction

**Rule.** A failed write that began at transaction level 0 is closed by the first of five events. They are the next statement, the next bridged write, the next transaction the application begins, a queue worker's next loop and application termination. The first three close the write only when `select 1` fails, because the bridge's transaction is then aborted.

**Why.** The bridge opened that transaction, and nothing else would close it. PostgreSQL refuses every further statement in an aborted transaction, and a `SAVEPOINT` too. Laravel begins a transaction through PDO, outside `Connection::beforeExecuting()`, so `Connection::transaction()` right after a caught failure once raised 25P02.

A statement can also start while the write's own statement runs. A `beforeExecuting` callback registered after the bridge's runs after the write opens, and before its statement. A `QueryExecuted` listener registered before the bridge's runs after the statement, and before `EventBridge::handleQuery()`. Such a statement finds the transaction healthy, so the bridge leaves the write open, and the write completes on its own `QueryExecuted`. Only a queue worker's next loop and termination commit a healthy write. So when a `QueryExecuted` listener registered before the bridge's throws, the write stays open, unmirrored, until one of those two.

**Code that must agree.** The `beforeExecuting` and `beforeStartingTransaction` callbacks in `EventBridge::watch()`, `EventBridge::finishFailed()`, the private `EventBridge::closeFailed()`, `EventBridge::releaseFailed()` and `EventBridge::begin()`. `EventBridge::closeFailed()` runs `select 1` before it closes a write, and leaves a healthy write open unless `EventBridge::releaseFailed()` asks. `Provider::boot()` listens for `Looping` and the terminating callbacks. Only a write whose statement started holds a transaction, so `EventBridge::finishFailed()` reaps only such a write; [INV-34](#inv-34-a-pending-write-opens-at-its-statement) records why.

**Pinned by.** `EventBridgeOutsideTransactionTest::it_releases_the_transaction_left_by_a_database_refusal_before_the_next_transaction_begins()` pins the transaction begin. `EventBridgeOutsideTransactionTest::it_commits_and_mirrors_a_write_whose_statement_an_earlier_query_executed_listener_follows_with_a_read()`, `EventBridgeOutsideTransactionTest::it_mirrors_a_write_whose_statement_a_later_before_executing_callback_precedes_with_a_read()` and `EventBridgeOutsideTransactionTest::it_mirrors_both_writes_when_an_earlier_query_executed_listener_makes_a_bridged_write_after_the_statement()` pin a statement in the window. `EventBridgeOutsideTransactionTest::it_rolls_back_its_transaction_before_the_next_statement_after_a_database_refusal_outside_a_transaction()`, `EventBridgeOutsideTransactionTest::it_releases_the_transaction_left_by_a_database_refusal_on_the_next_bridged_write()`, `EventBridgeOutsideTransactionTest::it_rolls_back_its_transaction_when_a_queued_bridged_write_fails_so_the_worker_records_the_failed_job()` and `EventBridgeOutsideTransactionTest::it_releases_the_transaction_left_by_a_database_refusal_when_the_application_terminates()`.

## INV-20: Inside a caller's transaction, a failure behaves as a native one

**Rule.** Inside a caller's transaction, the bridge works in a savepoint Laravel does not count. A PHP failure rolls back only that savepoint. A failed statement leaves the caller's transaction aborted, as a native failed statement would.

**Why.** The caller owns its transaction and decides how to recover from a failed statement.

**Code that must agree.** The private `EventBridge::open()` names the savepoint, and `EventBridge::close()` rolls it back or releases it. `EventBridge::complete()` runs the replay inside `Connection::transaction()`. The `beforeExecuting` callback in `EventBridge::watch()` and `EventBridge::finishFailed()` drop a savepoint write whose statement failed, without a rollback. A failed statement shows as a failed `select 1`, or as a level below the write's, after the caller rolled back past its savepoint. A healthy savepoint write stays open, as [INV-19](#inv-19-a-failed-write-at-level-0-releases-its-transaction) describes for level 0.

**Pinned by.** `EventBridgeOutsideTransactionTest::it_leaves_a_caller_transaction_aborted_after_a_database_refusal_inside_it_as_a_native_write_would()`, `EventBridgeTest::it_leaves_the_callers_transaction_usable_after_a_database_refusal()` and `EventBridgeTest::it_rolls_back_the_write_and_its_after_commit_work_when_a_mirrored_listener_throws()`. The last registers after-commit work in the listener that throws, catches the throw inside a caller's transaction and commits it, so the rejected work would run if the rollback kept it. `EventBridgeTest::it_mirrors_a_write_whose_statement_an_earlier_query_executed_listener_follows_with_a_read_inside_a_callers_transaction()` pins a healthy savepoint write.

## INV-21: A faked dispatcher cannot hide a mirrored write

**Rule.** A mirrored model's own write throws `CompatibilityEventMirrorBypassed` before its statement under a faked dispatcher. That holds when the model dispatcher is an `EventFake` that recorded the write's beginning event for that instance during that event's own dispatch. The fake recorded the event instead of running its listeners, so the bridge forgets the write it began for that event. An event the fake recorded earlier does not count, so a write after `EventFake::except()` mirrors.

**Why.** A test that fakes every event and writes through a mirrored model proves nothing about the other side. `EventFake::except()` changes which events the fake records, and keeps the events it recorded. A check of the whole record once refused every later write of the same instance.

**Code that must agree.** `EventBridge::fireModelEvent()` counts the fake's recorded beginning events for the instance through the private `EventBridge::recorded()`, before and after the dispatch. It forgets the write when the count grew. `EventBridge::markOwnStatement()` calls the private `EventBridge::guard()` when the model has no pending write to claim. The guard reads `MirrorIndex::forModel()` and asks `EventBridge::recorded()` about each of `ModelEvent::beginning()`. It ignores a model in no mirrored map. Inside `EventBridge::withoutMirroring()`, `EventBridge::markOwnStatement()` returns before the guard. A raw write runs no model method, so it never throws.

**Pinned by.** `EventBridgeTest::it_fails_loudly_when_a_test_fakes_the_model_events()`, `EventBridgeTest::it_fails_loudly_for_each_relation_a_faked_dispatcher_bypasses()`, `EventBridgeTest::it_mirrors_under_a_fake_that_leaves_model_events_alone()`, `EventBridgeTest::it_switches_the_mirror_off_only_when_a_test_says_so()` and `EventBridgeTest::it_lets_a_raw_write_through_after_a_faked_write_with_the_mirror_off()`. `EventBridgeTest::it_mirrors_a_write_once_the_fake_stops_faking_the_beginning_event_it_recorded_for_the_same_instance()` pins `EventFake::except()`. `HasCompatibilityTest::it_stops_a_write_under_a_faked_dispatcher_before_its_statement_reaches_the_database()` pins the throw before the statement, for an update, an insert and a delete. `HasCompatibilityTest::it_leaves_the_writes_of_a_model_in_no_mirrored_map_alone_under_a_fake()` pins the model in no map.

## INV-22: Compiled identifiers are full words

**Rule.** Every name the compiler adds is a full word: `previous_row`, `affected_rows`, `key_<alias>`, `created_key`, the object prefix and the function suffixes. An alias is a lowercase identifier other than `new`, `old` and the PostgreSQL reserved words. It is also no variable the triggers declare: not `previous_row`, `affected_rows` or `created_key`, and no name that starts with `key_`.

**Why.** A reader of the compiled SQL should not decode abbreviations. A reserved word as an alias would fail the install with a syntax error. An alias that names a variable makes PL/pgSQL refuse every reference to it as ambiguous, so every update would fail.

**Code that must agree.** `ResolvedMap::of()`, `ReservedWords::POSTGRESQL` and `ResolvedMap::VARIABLES`. `Compiler::variables()` names `previous_row`, `affected_rows` and `key_<alias>`, and `Compiler::primaryInsertFunction()` names `created_key`.

**Pinned by.** `InstallerTest::it_compiles_only_full_word_aliases_variables_and_object_names()` and `ResolvedMapTest::it_refuses_an_alias_that_is_a_reserved_postgresql_word()`. `ResolvedMapTest::it_refuses_an_alias_that_names_a_variable_the_compiled_triggers_declare()` pins the variables. `ReservedWordsTest::it_lists_every_word_the_server_reserves_as_an_alias()` checks `ReservedWords::POSTGRESQL` against the server. The first compiles the workbench maps, whose aliases are full words too. An application chooses its own aliases.

## INV-23: A refused-state check is serialized per record

**Rule.** A refuse function on a dependent's table or the retained table first takes `FOR KEY SHARE` on the primary row its row links, then `pg_advisory_xact_lock()`. The advisory lock's key is the refuse function's name, a colon and the row's primary foreign key, hashed with `hashtextextended()`. A refuse function on the primary table takes no lock.

**Why.** A condition that reads other rows of the same record would otherwise miss a concurrent writer's uncommitted row, and both writers would commit the state. The key must name both parts. Without the function name, two states would wait on each other. Without the primary foreign key, every writer of the table would wait on one lock. The primary row lock comes first so that the refused-state lock joins INV-1's order. INV-1 records the deadlock path that remains. A primary row has no primary foreign key, so the primary table stays unserialized. [0016](decisions/0016-a-refused-state-on-the-primary-table-is-not-serialized.md) records that limit.

**Code that must agree.** `Compiler::refuseFunction()` builds the lock from `ResolvedMap::refuseFunctionName()`, `ResolvedMap::dependent()` and `ResolvedMap::primaryForeignKey()`, or from the previous model's primary foreign key. The two locks are the function's first statements, before the `IF EXISTS` check. `Compiler::function()` declares no volatility, so the check after the wait reads a new snapshot under READ COMMITTED.

**Pinned by.** `InstallerTest::it_makes_a_concurrent_write_wait_for_the_refused_state_check_of_the_same_record()`, which writes from a second connection. `InstallerTest::it_does_not_deadlock_a_write_through_the_view_against_a_writer_holding_the_refused_state_lock()` pins the primary row lock. No test pins the primary-table limit or the REPEATABLE READ limit.

## INV-24: Each Installer method is atomic

**Rule.** `Installer::install()`, `Installer::recompile()` and `Installer::uninstall()` each run every statement inside one `Connection::transaction()`. Inside a caller's transaction, that is a savepoint.

**Why.** Each method drops the map's triggers before it creates or drops anything else, and a recompile drops the view too. A failure part way would leave a half-installed map, or a map without its triggers. A new primary row would then get no retained row. A concurrent writer waits on the dropped triggers' locks until the commit.

**Code that must agree.** `Installer::install()` wraps `Installer::apply()` and `Installer::copyPrivileges()`. `Installer::recompile()` wraps the private `Installer::viewGrants()`, `Installer::apply()` and the grants it restores. `Installer::uninstall()` wraps `Installer::dropObjects()` and the `DROP VIEW`. The checks in `Installer::install()` for an existing view and for views that read the retained table stay outside, because each throws before any change. Every refusal in `Installer::apply()` throws inside the transaction, before its first change.

**Pinned by.** `InstallerTest::it_leaves_nothing_behind_when_an_install_fails()`, `InstallerTest::it_keeps_the_installed_compatibility_map_when_a_recompile_fails()` and `InstallerTest::it_keeps_the_installed_compatibility_map_when_an_uninstall_fails()`. `InstallerTest` runs outside a test transaction, so these tests see a real commit and rollback.

## INV-25: A delete through the previous model mirrors every row it removes

**Rule.** A delete through the previous model that removes the row mirrors every dependent row under the record's primary foreign key. That includes a row another transaction commits before the bridge locks the primary row, when the dependent's primary foreign key has a foreign key constraint or its table has a refuse function ([INV-1](#inv-1-locks-follow-one-order) states the limit). A soft delete mirrors only the rows the view reads.

**Why.** The delete trigger removes every dependent row of the primary row, including rows the view does not read. Each removed row must raise its own delete events.

**Code that must agree.** `Compiler::deleteFunction()` deletes by primary foreign key. `KeyTranslator::dependentKeys()` selects by the same key. The private `AffectedRecords::removed()` turns those keys into records when the private `AffectedRecords::removes()` holds. `AffectedRecords::of()` calls it to find the records. `AffectedRecords::before()` calls `AffectedRecords::of()` a second time under the locks, so it finds newcomers too. **Pinned by.** `EventBridgeTest::it_raises_the_force_delete_events_of_every_dependent_row_a_previous_model_force_delete_removes()`. `EventBridgeOutsideTransactionTest::it_raises_the_force_delete_events_of_a_dependent_row_committed_before_the_primary_record_is_locked()` pins the newcomer, which a second connection commits. `AffectedRecordsTest::it_finds_every_dependent_row_a_previous_model_delete_removes()`, `AffectedRecordsTest::it_keeps_a_soft_delete_to_the_dependent_rows_the_previous_model_reads()` and `KeyTranslatorTest::it_lists_every_dependent_row_under_the_primary_row_of_a_previous_key()` pin the rows the bridge finds. `AffectedRecordsTest::it_locks_a_dependent_row_that_appears_under_the_first_locks_after_them_and_snapshots_it()` pins the newcomer's lock and snapshot.

## INV-33: A pending write completes only on its own statement

**Rule.** A pending write opens and completes only on the statement its model's own write method sends. The model marks that statement itself, through `HasCompatibility`, and the bridge reads no call stack. The armed write opens only on a statement whose first keyword is `INSERT`, `UPDATE` or `DELETE`. It completes only on that statement's `QueryExecuted`. [INV-50](#inv-50-every-mapped-model-marks-its-own-statement) requires the mark of every mapped model.

**Why.** A listener of the beginning event can write the same table, or the same record, before the model's own statement. The bridge once matched each statement's SQL text against the model. An increment's JSON-path or qualified extra and an `IS DISTINCT FROM` value each defeated that match. A miss sent the model's own statement with no events mirrored, no lock and no snapshot. Laravel 12 and 13 call `Model::setKeysForSaveQuery()` and `Model::getAttributesForInsert()` only inside the model's own write method, after its beginning event. No listener's query passes through them, so a mark there needs no guess. An earlier `beforeExecuting` callback can still run a `SELECT` between the arm and the model's own statement. That read would otherwise open the write, and complete it before the model's statement ran. A later `beforeExecuting` callback can run a statement after the write opens, and its `QueryExecuted` once completed the write before the model's statement ran.

**Code that must agree.** `HasCompatibility::setKeysForSaveQuery()` hands the save query of an update, an increment, a decrement, a delete, a soft delete or a force delete to `EventBridge::markOwnStatement()`. `HasCompatibility::getAttributesForInsert()` marks an insert. `EventBridge::markOwnStatement()` claims the topmost unclaimed pending write of the same instance, begun under the current model dispatcher, and sets `PendingMirroredWrite::$claimed`. It claims nothing inside `EventBridge::withoutMirroring()`. A save query arms its write from a `beforeQuery` callback, when the query runs, and an insert arms its write at once. The `beforeExecuting` callback in `EventBridge::watch()` asks the private `EventBridge::writes()` for the statement's first keyword. It opens the armed write on the connection's next `INSERT`, `UPDATE` or `DELETE`. The private `EventBridge::open()` records that statement's SQL string and bindings in `PendingMirroredWrite::$statement` and `PendingMirroredWrite::$bindings`. `EventBridge::handleQuery()` completes the open write only on a `QueryExecuted` whose SQL and bindings are identical to them. It parses neither.

**Pinned by.** Each test of `HasCompatibilityTest` named for an instance write method pins that method, with a listener that writes through the same instance's `Model::newQuery()`. `HasCompatibilityTest::it_covers_each_public_instance_write_method_of_eloquent_with_a_test_of_its_own()` fails when a Laravel version adds a write method that no test covers. `HasCompatibilityTest::it_mirrors_a_write_on_its_own_statement_and_not_on_a_quiet_write_of_the_same_instance_inside_its_listener()` pins the dispatcher check. `HasCompatibilityTest::it_mirrors_a_write_on_its_own_statement_and_not_on_a_write_of_the_same_instance_its_listener_makes_without_mirroring()` pins the check inside `EventBridge::withoutMirroring()`. `HasCompatibilityTest::it_opens_an_armed_write_on_its_own_update_and_not_on_a_select_an_earlier_callback_runs_first()` pins the first keyword. `EventBridgeOutsideTransactionTest::it_mirrors_a_write_whose_statement_a_later_before_executing_callback_precedes_with_a_read()` pins the completion on the write's own `QueryExecuted`. `EventBridgeTest::it_mirrors_an_increment_or_decrement_whose_extra_names_a_qualified_column_or_a_json_path()`, `EventBridgeTest::it_mirrors_an_increment_or_decrement_of_each_column_whose_extra_names_a_qualified_column_or_a_json_path()` and `EventBridgeTest::it_mirrors_a_save_that_sets_a_raw_is_distinct_from_expression_beside_another_attribute()` pin the forms that defeated the SQL match. `EventBridgeTest::it_mirrors_a_write_on_its_own_statement_and_not_on_a_later_listeners_write_to_the_same_table()`, `EventBridgeTest::it_mirrors_a_write_on_its_own_statement_and_not_on_a_later_listeners_write_to_the_same_record()` and `EventBridgeTest::it_mirrors_a_create_on_its_own_insert_and_not_on_a_later_listeners_insert_into_the_same_table()` pin a listener's write to the same table or record. So do `EventBridgeTest::it_mirrors_an_increment_on_its_own_statement_and_not_on_a_later_listeners_write_to_the_same_record()`, `EventBridgeTest::it_mirrors_a_save_on_its_own_statement_and_not_on_a_later_listeners_write_of_some_or_all_of_its_changes()` and `EventBridgeOutsideTransactionTest::it_locks_and_mirrors_a_write_on_its_own_statement_and_not_on_a_listeners_update_of_the_same_columns_outside_a_transaction()`.

The rule has three limits:

- A write statement that runs between the arm and the model's own statement opens the write. A later `beforeQuery` callback on the model's own query can run one, and so can a `beforeExecuting` callback registered before the bridge's.
- A throw between the arm and the bridge's `beforeExecuting` callback leaves the write armed. The connection's next write statement then opens it, unless the next beginning event, `Looping` or termination drops it first.
- An insert that Laravel skips, for a model with no attributes, arms a write that no statement follows. The model's saved event forgets it.

## INV-34: A pending write opens at its statement

**Rule.** A beginning event only records a pending write. When that write's own statement starts, the bridge opens its transaction or savepoint, locks the affected records and reads them. It opens only a write its model's own write method armed. `EventBridge::finishFailed()` reaps only a write whose statement started. Before each statement, the bridge closes every write on top of the stack whose statement failed, as a failed `select 1` shows. It stops at a healthy one, as [INV-19](#inv-19-a-failed-write-at-level-0-releases-its-transaction) describes. Before a write statement with an armed write, it also forgets every other write above the armed one. It forgets every unclaimed, unsent write of the armed write's instance and operation at the armed write's depth too, then opens the armed one.

**Why.** Code can throw between the beginning event and the statement: a cast, the encrypter or a later listener. A transaction opened at the event would then outlive the write, and hold its locks for the rest of the request. A listener on the beginning event can also write another mapped model. Its write would otherwise reap the outer write before the outer statement ran, and the outer write would mirror nothing. When that inner write fails and the listener catches the failure, the outer statement comes next. A callback that stopped after it closed the inner write would let the outer statement run with nothing opened. A save that throws after its beginning event, and before its statement, leaves its write on the stack. A later write without events to the same record would otherwise complete it, and the bridge would mirror a write the application made without events. A retry of that save, or of a delete whose `touchOwners()` threw, then began a second write of the same instance at the same depth. Its own statement completed it, and its finishing event paired with the first write, found it unclaimed and refused the retry as unmarked. One write method fires one beginning event, so a second at that depth means the first method has returned.

**Code that must agree.** `EventBridge::begin()` pushes the `PendingMirroredWrite`, and drops an armed write whose statement never came. `EventBridge::markOwnStatement()` claims the write, and arms it. The `beforeExecuting` callback in `EventBridge::watch()` loops over the top of the stack. It closes or forgets each write whose statement failed, through the private `EventBridge::closeFailed()`, and stops at a healthy one. Before a write statement with an armed write, it also forgets each other write above that one. Each is an unsent write whose method has returned. It then forgets each unclaimed, unsent write of the same instance, operation and depth as the armed write. It then calls the private `EventBridge::open()`, which sets `PendingMirroredWrite::$statementSent`. Without an armed write, a statement leaves the stack alone, so an unclaimed write never opens. `EventBridge::finishFailed()` stops at a write whose statement has not started. `EventBridge::fireModelEvent()` forgets a write whose beginning dispatch returns false or throws. `EventBridge::finish()` forgets an unsent write at its own finishing event. `EventBridge::releaseFailed()` forgets every write that holds no transaction.

**Pinned by.** `EventBridgeOutsideTransactionTest::it_opens_no_transaction_and_takes_no_lock_when_a_listener_throws_before_the_statement()`, with an updating listener that throws, and a later write without events that mirrors nothing. `EventBridgeTest::it_mirrors_nothing_for_a_later_write_without_events_to_the_record_of_a_vetoed_save()` pins a vetoed save. `HasCompatibilityTest::it_holds_no_model_after_a_save_an_updating_listener_vetoes_and_an_increment()` and `HasCompatibilityTest::it_holds_no_model_after_an_updating_listener_throws_and_an_increment()` pin that a veto and a throw leave no write behind. `EventBridgeOutsideTransactionTest::it_mirrors_both_writes_when_a_beginning_listener_writes_another_mapped_model_outside_a_transaction()` and `EventBridgeTest::it_mirrors_both_writes_when_a_beginning_listener_writes_another_mapped_model_inside_a_callers_transaction()` pin the nested write at both levels. `EventBridgeOutsideTransactionTest::it_mirrors_the_outer_write_when_a_beginning_listener_catches_a_refused_write_to_another_mapped_model_outside_a_transaction()` and `EventBridgeTest::it_mirrors_the_outer_write_when_a_beginning_listener_catches_a_refused_write_to_another_mapped_model_inside_a_callers_transaction()` pin a failed nested write. `EventBridgeOutsideTransactionTest::it_mirrors_a_delete_made_again_after_its_touch_failed_before_its_statement()` pins a retried delete, at level 0 and in a retry by `Connection::transaction()`.

A vetoed write, and a write whose beginning listener throws, leave the stack when their dispatch ends. Another write whose statement never comes stays until one of five things removes it. They are a write that opens below it, a write of the same instance and operation that opens at its depth, its own finishing event, the next `Looping` event and termination. A cast that throws after the beginning event leaves such a write. It holds no transaction and no lock.

## INV-35: A pending write leaves the stack only once its close finishes

**Rule.** The bridge forgets a pending write only after its commit, rollback or savepoint release finishes. When a commit at level 0 fails, it rolls the connection back to the write's level, forgets the write and rethrows. A completed write leaves the stack once its close finishes. Each finishing event pairs with its own write or with none, by the dispatch depth of its model's write.

**Why.** A `COMMIT` can fail, for example on a deferred constraint or a lost connection. Laravel then still counts the bridge's transaction. A write forgotten before its commit would leave that level with nothing to close it. A listener can also save the same instance inside its write. A finishing event that paired by instance alone found the outer write when its own had gone. The bridge then forgot the outer write, and the outer statement mirrored nothing. A save with nothing to change, and the saved event `touchOwners()` fires on a parent, did the same. An earlier design kept each completed write until its last finishing event, chosen by counting saving events. A clean save, a vetoed save or an ignored `saveOrIgnore()` left that count or a write behind. The write then held its model until `Looping` or termination. Eloquent fires a write's own events from one method, outside any listener, so the dispatch depth tells them apart from a listener's write.

**Code that must agree.** The private `EventBridge::endTransaction()` commits, rolls back or releases the savepoint, and forgets the write only when that throws. It commits and rolls back outside `EventBridge::internally()`. Laravel runs after-commit work inside `Connection::commit()`, so a mapped write there opens, locks and mirrors like any other. `EventBridge::close()` calls it, then forgets the write. `EventBridge::complete()` ends through `EventBridge::close()`, so a completed write leaves the stack. Laravel's `Connection::rollBack()` resets the level whether or not PDO still holds the transaction. `HasCompatibility::fireModelEvent()` hands every model event to `EventBridge::fireModelEvent()`. That raises the dispatch depth around the dispatch, and lowers it in a `finally` block. `EventBridge::begin()` records the depth in `PendingMirroredWrite::$depth`. `EventBridge::finish()` takes only the instance's writes at the current depth: of the event's operation for created, updated or deleted, and of either save operation for saved.

**Pinned by.** `EventBridgeOutsideTransactionTest::it_rolls_back_a_mirrored_write_whose_commit_fails_and_leaves_the_connection_outside_a_transaction()`, which fails the commit with a deferred constraint trigger. `HasCompatibilityTest::it_mirrors_both_updates_when_an_updating_listener_saves_the_same_instance_and_then_changes_another_attribute()` pins the pairing, with an `updating` listener that saves the same instance and then changes another attribute. `HasCompatibilityTest::it_mirrors_both_updates_when_an_updating_listener_saves_the_same_instance_twice_and_then_changes_another_attribute()` pins a second save with nothing to change. `EventBridgeTest::it_mirrors_both_writes_when_an_updating_listener_saves_a_child_that_touches_the_same_instance()` pins the saved event of `touchOwners()`. `EventBridgeTest::it_mirrors_a_delete_whose_touched_owner_in_no_map_saves_the_same_instance_from_its_saved_listener()` pins a saved event at a delete's depth, which takes no delete. `EventBridgeOutsideTransactionTest::it_mirrors_a_mapped_write_that_an_after_commit_callback_of_a_mirrored_listener_makes()` pins the commit outside `EventBridge::internally()`. Six tests hold a weak reference to the model and pin that nothing stays behind. They are `HasCompatibilityTest::it_holds_no_model_after_a_save_with_nothing_to_change_and_an_increment()`, `HasCompatibilityTest::it_holds_no_model_after_many_saves_with_nothing_to_change_and_their_increments()`, `HasCompatibilityTest::it_holds_no_model_after_a_save_an_updating_listener_vetoes_and_an_increment()`, `HasCompatibilityTest::it_holds_no_model_after_an_updating_listener_throws_and_an_increment()`, `HasCompatibilityTest::it_holds_no_model_after_a_save_vetoed_inside_the_same_instances_save_that_then_sends_no_statement()` and `HasCompatibilityTest::it_holds_no_model_after_an_ignored_save_or_ignore()`.

## INV-36: An attribute without a btree equality compares as text

**Rule.** The triggers compare an attribute as text when its type has no default btree equality operator. That covers the read-only check, `SqlFragments::changed()`, each `CASE WHEN` in `Compiler::update()` and the conflict check's `ROW()`. `json` and `xml` are such types, and so is a domain over one. A composite type compares as text too.

**Why.** `json` has no `=` operator, so `IS DISTINCT FROM` fails on every update that compares it, and install still succeeds. Text keeps a whitespace or key-order change the caller wrote. A cast to `jsonb` would discard that change.

**Code that must agree.** `ColumnCatalog::equatable()` follows a domain to its base type and an array to its element type. The private `Compiler::compared()`, `Compiler::comparesAsText()` and `Compiler::comparedAsText()` apply it. `SqlFragments::changed()` takes the columns it compares as text. A retained attribute takes its column's catalog type, and a mapped attribute its `Attribute::asType()`.

**Pinned by.** `CompilerTest::it_compares_a_json_attribute_by_its_text_in_every_write_through_the_view()`, with a writable and a read-only retained `json` attribute and a mapped `json` attribute. `ColumnCatalogTest::it_tells_whether_a_type_has_a_default_btree_equality_operator()` and `SqlFragmentsTest::it_tells_whether_a_column_compared_as_text_changed_by_its_text()` pin the parts.

## INV-37: A trigger function runs only for its own relation

**Rule.** Every compiled function refuses with CM001 when `TG_RELID` names a relation other than its own or a partition of its own. Install and recompile revoke `EXECUTE` on each function from `PUBLIC`. Every built-in function the compiled SQL calls is qualified with `pg_catalog`. Only trusted roles may create objects in the installation schema, and the package does not check that.

**Why.** The functions are `SECURITY DEFINER`. Any role that can create a temporary table could otherwise attach one as a trigger there. It would then run the body with the owner's rights, for example to delete retained rows. PostgreSQL checks `EXECUTE` when a trigger is created, not when it fires, so the revoke leaves the map's own triggers working. PostgreSQL clones a row trigger on a partitioned table onto each partition, and the clone fires with the partition as `TG_RELID`. Only the partitioned table's owner can attach a partition, so accepting the partition root admits no other role's table.

PostgreSQL picks a function by its closest argument match, whatever its schema's place on the search path. A `hashtextextended(text, integer)` in the installation schema therefore ran in place of the built-in `hashtextextended(text, bigint)`, with the owner's rights. A qualified call finds only the built-in. An operator resolves the same way, and so does every function and operator in a map's own expressions. The compiled SQL leaves those unqualified, so the schema's privileges are what keep another role's code out. A type name has no argument match, and `pg_catalog` precedes the installation schema, so built-in type names stay unqualified.

**Code that must agree.** `Compiler::function()` writes the check as the first statement of every body, and accepts a relation whose `pg_partition_root()` is its own. `Compiler::compile()` adds a `REVOKE` after each function. The relation is the view for the insert, update and delete functions, and the primary table for the primary insert and primary delete functions. A refuse function's relation is its checked table, and a designate function's is its dependent's table. `Compiler::function()`, `Compiler::refuseFunction()`, `Compiler::skipWhileApplying()`, `Compiler::insertFunction()` and `Compiler::primaryInsertFunction()` qualify their built-in calls. `ColumnCatalog::of()` qualifies the `nextval()` default it builds for a `GENERATED BY DEFAULT` identity.

**Pinned by.** `CompilerTest::it_refuses_to_run_a_trigger_function_fired_on_any_relation_but_its_own()`, `CompilerTest::it_refuses_the_primary_delete_function_fired_on_another_table_before_it_deletes_a_retained_row()`, `CompilerTest::it_runs_its_trigger_functions_on_the_partitions_of_a_partitioned_current_table()` and `InstallerTest::it_lets_no_other_role_execute_a_trigger_function_after_an_install_or_a_recompile()`. `InstallerTest::it_lets_a_role_granted_a_retained_column_write_that_column_through_the_view()` pins that a granted role still writes through the view. `CompilerTest::it_calls_no_function_of_the_installation_schema_that_takes_the_name_of_a_built_in_function()` pins the qualified calls. Its overloads of `hashtextextended()`, `concat()` and `pg_partition_root()` raise when called, and every write and the relation check still succeed. No test pins the qualified `set_config()`, `current_setting()`, `pg_advisory_xact_lock()` or `nextval()` calls. Nothing checks the installation schema's privileges.

## INV-38: The schema refuses a table with row-level security

**Rule.** `Installer::install()` and `Installer::recompile()` refuse a map whose retained table or any current table has row-level security enabled.

**Why.** The view reads with its owner's rights, and the `SECURITY DEFINER` triggers write with them. A role granted the view would read and write past the table's policies, for example into another tenant's rows. The package cannot enforce a caller's policies yet.

**Code that must agree.** The private `Installer::apply()`, before it compiles, for both callers.

**Pinned by.** `InstallerTest::it_refuses_to_install_or_recompile_over_a_table_with_row_level_security()`.

## INV-39: Every insert fills each required column

**Rule.** Compile refuses a `NOT NULL` column without a default that an insert leaves empty. It checks the retained table on a primary insert and on an insert through the view. It checks the primary table and each inserted dependent's table on an insert through the view. An identity or generated column counts as filled.

**Why.** Install would otherwise succeed, and every insert into the current table would then fail with 23502, factories and seeders included.

**Code that must agree.** The private `Compiler::validateFills()` and `Compiler::refuseEmpty()`, with `Column::needsAValue()` and `Column::$generated` from `ColumnCatalog::of()`. The columns they count as filled must match what `Compiler::primaryInsertFunction()`, `Compiler::insertFunction()` and `Compiler::dependentValues()` insert, so both read the private `Compiler::insertAssignmentsTo()`. A dependent counts only when the view inserts its rows, so only when it has an attribute or a fill. A read-only mapped attribute counts, as [INV-49](#inv-49-an-insert-through-the-view-stores-a-read-only-attribute) requires. `Compiler::compile()` runs the check after it builds the functions, so a missing column refuses first. A column with a default counts as filled, so the insert must let that default fill it, as [INV-46](#inv-46-an-insert-through-the-view-keeps-a-not-null-columns-default) requires.

**Pinned by.** `CompilerTest::it_refuses_a_not_null_column_without_a_default_that_an_insert_leaves_empty()`, `CompilerTest::it_counts_a_filled_default_identity_or_generated_column_as_filled_on_every_insert()` and `ColumnTest::it_needs_a_value_from_every_insert_only_when_it_is_not_null_without_a_default_and_not_generated()`.

## INV-40: An insert through the view returns the row as the view reads it

**Rule.** Before `RETURN NEW`, the insert trigger reads every attribute back from the stored rows into `NEW`, as the view reads it.

**Why.** `INSERT ... RETURNING` reports `NEW`. Without the read it reports only what the caller sent: no default, fill or trigger value, and no value a read expression formats.

**Code that must agree.** `Compiler::insertFunction()` reads through `Compiler::read()`, which `Compiler::view()` uses too. The read leaves out the hidden states' filter, so a hidden record still returns its row.

**Pinned by.** `CompilerTest::it_returns_every_attribute_of_an_insert_through_the_view_as_the_view_reads_it()`, with a retained default, a primary fill, a retained trigger and a formatted read.

## INV-41: A recompile replaces the view and keeps its grants

**Rule.** `Installer::recompile()` drops the view and creates it again in its transaction. It saves the view's grants first and grants them again after, a column grant only when the new view has that column. It refuses with `InvalidCompatibilityMap` while another object depends on the view or uses its row type, and names each one. It also refuses, by name, a trigger or a rule on the view that is not the map's own. It never drops with `CASCADE`. The new view carries no grant its default privileges add, as [INV-48](#inv-48-the-new-view-carries-no-grant-its-default-privileges-add) requires.

**Why.** `CREATE OR REPLACE VIEW` cannot drop, retype or reorder a column. A dependent object would block the drop with a raw 2BP01 error, and `CASCADE` would drop that object silently. `DROP VIEW` drops a trigger or a rule on the view silently, even without `CASCADE`.

**Code that must agree.** `Installer::recompile()`, the private `Installer::viewGrants()` and the private `Installer::apply()`. `Installer::apply()` reads `pg_depend` for normal dependencies on the view and its row type, and for automatic ones from a trigger or a rule. A trigger named with the map's object prefix is the map's own, as for `Installer::dropObjects()`. `Installer::viewGrants()` saves a view with no explicit grants as its owner's default privileges, through `acldefault()`. It saves no grant of the recompiling role, which owns the new view.

**Pinned by.** `InstallerTest::it_recompiles_a_map_that_removes_retypes_or_reorders_an_attribute()`, `InstallerTest::it_keeps_every_grant_on_the_view_when_it_recompiles_the_view_anew()`, `InstallerTest::it_leaves_the_views_grants_as_they_are_when_it_recompiles()` and `InstallerTest::it_refuses_to_recompile_while_another_object_depends_on_the_view_and_names_it()`. `InstallerTest::it_refuses_to_recompile_while_an_object_uses_the_views_row_type_or_sits_on_the_view_and_names_it()` pins a function argument, a column, a trigger and a rule. [0022](decisions/0022-a-recompile-replaces-the-view-and-refuses-its-dependents.md) records the decision.

## INV-42: Only the compatibility view reads the retained table

**Rule.** `Installer::install()` refuses while another view or materialized view reads the retained table, and names each one.

**Why.** A view on the old table follows its rename and keeps reading the retained table. It then misses every mapped attribute, and the triggers never see its writes. [Adopting a map](adopting-a-map.md) describes how to point such a view at the compatibility view.

**Code that must agree.** `Installer::install()` finds the readers through `pg_depend` and `pg_rewrite`, before its transaction.

**Pinned by.** `InstallerTest::it_refuses_to_install_while_another_view_reads_the_retained_table_and_names_it()`, with a view and a materialized view.

## INV-43: The event bridge refuses a Parental model

**Rule.** `EventBridge::mirror()` refuses a map that names a class using a trait named Tightenco\Parental\HasChildren, which it finds through Laravel's `class_uses_recursive()`.

**Why.** Parental hydrates a child class, and the child fires its model events under its own class name. The bridge finds a model's maps by the exact class name, so it would silently mirror none of those writes. Its replays would also build the parent class, not the child.

**Code that must agree.** `EventBridge::mirror()` checks the previous model and every current model before it adds the map to its index. It resolves the map for its checks, and calls `CompatibilityMaps::register()` only after every check passes. So a refused map never reaches `compatibility:check`. The package adds no dependency on Parental.

**Pinned by.** `EventBridgeTest::it_refuses_to_mirror_a_map_that_names_a_model_whose_children_fire_events_under_their_own_classes()`, with the class as the previous, the primary and a dependent model. It also asserts that the registry and `compatibility:check` hold no map after the refusal. `EventBridgeTest::it_keeps_the_mirrored_map_registered_when_a_second_mirror_of_its_name_is_refused()` pins the same order for the repeated-mirror refusal.

## INV-44: No map expression ends a function body

**Rule.** `Compiler::function()` refuses a body that contains `$compatibility$`, the tag that quotes it.

**Why.** A fill, a condition, a read or a write expression with that tag would end the body early. The rest of the body would then run as SQL of its own when the install runs.

**Code that must agree.** `Compiler::function()`, which builds every function. A default lands in an `ALTER VIEW` statement, never in a body, so the check does not cover it.

**Pinned by.** `CompilerTest::it_refuses_at_compile_time_a_map_the_tables_cannot_store()`, in its `delimiter_in_fill` and `delimiter_in_condition` cases.

## INV-45: A generated column is read-only through the view

**Rule.** `ColumnCatalog::of()` reports no default for a generated column. `Compiler::validateColumns()` refuses a map whose attribute is not read-only and writes a generated column or a `GENERATED ALWAYS` identity column. The message names the attribute and the column, and says to declare it read-only. A `GENERATED BY DEFAULT` identity stays writable. An insert through the view leaves out a read-only attribute, retained or mapped, over a column the database always generates.

**Why.** `pg_attrdef` holds a generated column's expression. Reported as a default, it reaches `ALTER VIEW ... SET DEFAULT`, which PostgreSQL rejects because a default cannot reference a column. So a map that exposes a generated column would fail to install or recompile. A write of a value to a generated column, or to a `GENERATED ALWAYS` identity, fails on every write through the view. Compile refuses the map instead.

An insert that omits a `GENERATED BY DEFAULT` identity attribute takes the identity's next value. `ColumnCatalog::of()` reports that column's default as `nextval(pg_get_serial_sequence('<schema>.<table>', '<column>')::regclass)`. The table name carries its schema, because a view default runs on the writer's search path. A retained or primary attribute takes it as its view default, and [INV-46](#inv-46-an-insert-through-the-view-keeps-a-not-null-columns-default) fills every other insert target.

**Code that must agree.** `ColumnCatalog::of()`, which reads `attgenerated` and `attidentity` into `Column::$default`, `Column::$generated` and `Column::$alwaysGenerated`, and `Compiler::validateColumns()`. `Compiler::defaults()` takes the identity's default. `Compiler::insertFunction()` skips a retained attribute whose column has `Column::$alwaysGenerated`, and the private `Compiler::insertAssignmentsTo()` skips such a read-only mapped attribute. `Column::needsAValue()` keeps counting every generated and identity column as filled, so INV-39 still holds.

**Pinned by.** `ColumnCatalogTest::it_reads_an_identity_or_generated_column_as_generated_and_gives_a_generated_column_no_default()`, `ColumnTest::it_carries_whether_the_database_always_generates_its_value()`, `CompilerTest::it_refuses_a_writable_attribute_whose_column_the_database_always_generates()`, `CompilerTest::it_compiles_and_writes_a_writable_attribute_whose_column_is_a_default_identity()` and `InstallerTest::it_installs_and_recompiles_a_map_that_exposes_a_generated_column_read_only()`. `CompilerTest::it_lets_the_table_number_an_identity_retained_key_that_an_insert_through_the_view_omits()` pins a retained key of either identity kind. `CompilerTest::it_stores_a_read_only_mapped_attribute_on_an_insert_through_the_view_and_still_refuses_a_change_to_it()` pins a read-only mapped attribute over a `GENERATED ALWAYS` identity.

## INV-46: An insert through the view keeps a NOT NULL column's default

**Rule.** An insert through the view writes `COALESCE(<value>, <default>)` to each attribute's target column that is `NOT NULL` and has a catalog default. That covers the primary table, the retained targets of mapped attributes and each dependent's table. A nullable column with a default stores NULL when the insert omits its attribute.

**Why.** The insert writes every target column explicitly, so an omitted attribute's NULL replaced the column's default. A dependent's view column has no default, and a `writesTo()` expression of NULL is NULL. A `NOT NULL` column with a default then failed with 23502, although [INV-39](#inv-39-every-insert-fills-each-required-column) counted it as filled. An explicit NULL failed there anyway, so no insert that succeeded before changes.

**Code that must agree.** `Compiler::insertValues()` wraps each assignment's value, for `Compiler::insertFunction()` and both dependent inserts through `Compiler::dependentValues()`. The update trigger's create branch in `Compiler::updateDependent()` is one of them. `Column::$notNull` and `Column::$default` come from `ColumnCatalog::of()`. A fill from `fillWhenCreatedFromPrevious()` keeps its own expression.

**Pinned by.** `CompilerTest::it_writes_the_default_of_a_not_null_current_column_that_an_insert_through_the_view_leaves_empty()`, with a dependent insert, the update trigger's create branch, a primary `writesTo()` target and a nullable column.

## INV-47: A map's tables resolve in the current schema alone

**Rule.** Compile, install and recompile look up the retained table and every current table in `current_schema()` alone. A table that exists only in a later schema on the search path refuses at compile with `InvalidCompatibilityMap`: "the current table <table> does not exist".

**Why.** Each compiled function pins its `search_path` to the current schema, and its relation check names that schema. A table found further down the search path installed without error. Its trigger then landed on the other schema's table, and every insert there failed with 42P01. `Installer::uninstall()` and `Installer::recompile()` could not remove that trigger.

**Code that must agree.** `ColumnCatalog::of()` and every `to_regclass()` on a map table in `Installer` name the table as `quote_ident(current_schema()) || '.' || <table>`. The private `Installer::relation()` does the same for the view. `Compiler::validateColumns()` refuses a retained or current table that `ColumnCatalog::of()` does not find. `EventReplayer::changed()` reads column types through `ColumnCatalog`, so it also reads the current schema alone.

**Pinned by.** `CompilerTest::it_refuses_a_map_whose_current_table_is_outside_the_schema_it_installs_into()`, with the retained table in the current schema and the current tables in a later one.

## INV-48: The new view carries no grant its default privileges add

**Rule.** After `Installer::install()` or `Installer::recompile()` creates the view, it revokes every grant on the view that its owner does not hold. Install then copies the retained table's grants, and recompile restores the saved grants. So the view carries those grants alone.

**Why.** PostgreSQL applies `ALTER DEFAULT PRIVILEGES` to every view a role creates. A recompile would otherwise give back access a revoke had removed, such as `SELECT` for `PUBLIC`. A default `UPDATE` or `DELETE` grant would also reach the tables through the `SECURITY DEFINER` triggers.

**Code that must agree.** The private `Installer::revokeDefaultPrivileges()`, at the end of the private `Installer::apply()`, for both callers. It reads the grantees from `aclexplode()` of the view's ACL, and leaves the owner's own privileges as they are. `Installer::copyPrivileges()` and the restore in `Installer::recompile()` run after it.

**Pinned by.** `InstallerTest::it_keeps_every_grant_the_default_privileges_add_off_the_view_it_creates()`, for an install and a recompile, with default grants to `PUBLIC` and to a role.

## INV-49: An insert through the view stores a read-only attribute

**Rule.** A read-only attribute cannot change through the view, and an insert through the view still stores its value. A retained attribute stores into its own column, and a mapped attribute into its `storedAs()` column. A mapped attribute with only `readAs()` has no stored column, so it stores nothing. A read-only attribute stored in a column that a writable attribute writes stays out of the insert, as [INV-8](#inv-8-each-stored-column-has-one-owner) says. An attribute over a column the database always generates stays out of the insert, as [INV-45](#inv-45-a-generated-column-is-read-only-through-the-view) says. An omitted value takes the column's default, as [INV-46](#inv-46-an-insert-through-the-view-keeps-a-not-null-columns-default) says. The update trigger refuses a change to a read-only attribute with CM001.

**Why.** `Attribute::readOnlyBecause()` clears a mapped attribute's writes, and the insert wrote only those writes. So an Eloquent `create()` with a read-only mapped `created_at` left the stored column NULL, while the model held the value. Nothing raised. A read-only retained attribute was always stored, so the two kinds disagreed.

**Code that must agree.** The private `Compiler::insertAssignmentsTo()` adds each read-only mapped attribute's `storedAs()` target to an alias's writes, unless `ResolvedMap::writes()` reports a writable owner. `Compiler::insertFunction()` reads it for the primary, retained and dependent inserts, and for each dependent's default `createdWhen()` condition. `Compiler::validateFills()` reads it too, so [INV-39](#inv-39-every-insert-fills-each-required-column) counts such a column as filled. `Compiler::insertFunction()` writes each retained attribute, read-only or not. `Compiler::updateFunction()` refuses a change through `ResolvedMap::readOnlyAttributes()`. The update trigger's create branch in `Compiler::updateDependent()` reads `ResolvedMap::assignmentsTo()` alone, because an unchanged read-only value there is NULL.

**Pinned by.** `CompilerTest::it_stores_a_read_only_mapped_attribute_on_an_insert_through_the_view_and_still_refuses_a_change_to_it()`, through an Eloquent `create()`. It covers a primary column, a `NOT NULL` column with a default, a `GENERATED ALWAYS` identity, a dependent column and a dependent's `NOT NULL` column that only a read-only attribute fills. It also pins the refusal of an update. `InstallerTest::it_installs_and_recompiles_a_map_that_exposes_a_generated_column_read_only()` pins a read-only generated column.

## INV-50: Every mapped model marks its own statement

**Rule.** Every model of a mirrored map implements `Compatible` and uses `HasCompatibility`, and its `setKeysForSaveQuery()`, `getAttributesForInsert()` and `fireModelEvent()` resolve to the trait's methods. `EventBridge::mirror()` refuses any other map with `InvalidCompatibilityMap`. It also refuses a model that uses `Illuminate\Database\Eloquent\Relations\Concerns\AsPivot`, as every Eloquent pivot does. A created, updated or deleted event for an instance whose pending write no mark claimed refuses the write with `CompatibilityEventMirrorBypassed`.

**Why.** The bridge opens a write only on the statement its model marks, as [INV-33](#inv-33-a-pending-write-completes-only-on-its-own-statement) records. A model without the trait would mark nothing. So would a model whose own declaration replaces a method of the trait, because PHP gives a class's method precedence over a trait's. The bridge also sees a model's events only through `HasCompatibility::fireModelEvent()`. Its writes would then mirror nothing, with no lock and no snapshot, and nothing would say so. A future Laravel write path that calls neither method has the same effect. `Illuminate\Database\Eloquent\Relations\Concerns\AsPivot::delete()` is such a path today. It deletes a pivot loaded without its key through its own query, so the delete reached the database before the deleted event refused it. Eloquent fires those three events only after its own statement, so an unclaimed write there proves a statement ran without its mark.

**Code that must agree.** `EventBridge::mirror()` checks the previous model and every current model, after the Parental check of [INV-43](#inv-43-the-event-bridge-refuses-a-parental-model) and before it registers the map. It finds the interface through `is_subclass_of()` and the trait through `class_uses_recursive()`. Through `\ReflectionMethod`, it compares the file and the first line of each resolved method with those of the trait's method. So a declaration in the class, in any class it extends or in another trait fails, and a trait the class inherits passes. It finds the pivot trait through `class_uses_recursive()` too, before the mark check. The `HasCompatibilityMustNotRedeclareWriteHooks` PHPStan rule makes the same comparison for a named class. `EventBridge::finish()` forgets the unclaimed write, then throws `CompatibilityEventMirrorBypassed::byUnmarkedStatement()`. A saved event can follow a save that sent no statement, so it never throws.

**Pinned by.** `EventBridgeTest::it_refuses_to_mirror_a_map_that_names_a_model_without_the_interface_and_the_trait_that_mark_its_own_statement()`, with a model that has neither, the interface alone or the trait alone. `EventBridgeTest::it_refuses_to_mirror_a_map_whose_model_redeclares_a_method_the_trait_marks_its_own_statement_from()` and `EventBridgeTest::it_refuses_to_mirror_a_map_whose_model_redeclares_the_method_the_trait_sees_its_model_events_through()` pin a declaration of each method in the class and in a subclass. Between them they place the model as the previous, the primary and a dependent model. Both assert that the registry holds no map after the refusal. `EventBridgeTest::it_mirrors_a_map_whose_model_inherits_the_trait_from_the_class_it_extends()` pins an inherited trait. `EventBridgeTest::it_refuses_to_mirror_a_map_that_names_a_pivot_model()` pins the pivot refusal in each role. `HasCompatibilityTest::it_refuses_a_write_whose_statement_ran_without_its_mark_and_rolls_it_back_inside_a_transaction()` pins the runtime refusal at each of the three events, and its rollback. It fires each event through the model's own `fireModelEvent()`, as a write method that builds its own statement would. `EventBridgeOutsideTransactionTest::it_refuses_a_write_whose_statement_ran_without_its_mark_and_leaves_the_statement_committed_outside_a_transaction()` pins the refusal at level 0: the statement stays committed, and the connection stays outside a transaction.
